# Security: the embedded Pluto scripting runtime

`rana-socket` embeds **Pluto** (a Lua 5.4/5.5 fork) and runs `.pluto` scripts
that are **generated by an LLM at runtime** (e.g. `ask.pluto`, `lookup_machine.pluto`).
These scripts are **untrusted**: a model can hallucinate calls it was never
supposed to make. The runtime is therefore locked down by default and requires
no configuration to stay safe.

## Threat model

| Capability | Risk if exposed to a malicious/hallucinated script |
| --- | --- |
| `os`, `io` | Arbitrary process execution, filesystem read/write, env leaks |
| `ffi` (`lffi.cpp`) | `ffi.open` → load arbitrary `.so`; `ffi.alloc/write/read/callback` → native memory R/W and code execution |
| `socket` / `http` / `tls` | Direct outbound network: exfiltration, SSRF against internal services |
| `crypto` / `wasm` | Decryption of secrets, arbitrary code via WASM |
| `load` / `loadfile` / `dofile` | Execute arbitrary/compiled Lua from disk or a string |
| `package.*` (`require`, `loadlib`) | Load any installed C/Lua module, including the above |
| Compiled Pluto bytecode | Bypass source review / hide logic in a binary blob |

## Defense layers (all on by default)

### 1. Compile-time flags (predep `make` stage `pluto`, `predep.toml`)
Pluto is **not** compiled in-tree. `predep` clones it and builds
`vendor/pluto/src/libpluto.so` via Pluto's own Makefile (`builder = "pluto"` →
`[[stages]] name = "pluto" type = "make"`), passing the hardening flags through
`MYCFLAGS`:
- `PLUTO_DISABLE_COMPILED` — reject precompiled bytecode; only source may load.
- `PLUTO_NO_BINARIES` — disables `ffi.open` / `os.execute` / loading of `.so`.
- `PLUTO_DISABLE_HTTP_COMPLETELY` — makes Pluto's `http.*` fail closed even
  if the library were somehow loaded.
- `PLUTO_ETL_ENABLE` / `PLUTO_ILP_ENABLE` — enable Pluto language features the
  scripts rely on.
`rana-socketd` links the prebuilt `libpluto.so` (see `socket/premake5.lua`) with
an rpath of `$ORIGIN` + the build path, and `predep install` ships the `.so`
next to the binary.

### 2. Runtime lockdown (`LuaRuntime::new_state`, `luafunctions.cpp`)
**Always applied — there is no config toggle.** Instead of Pluto's
`luaL_openlibs(L)` (which opens *everything* and, worse, preloads `ffi`,
`socket`, `http`, `crypto`, `wasm` into `package.preload` so `require` bypasses
global stripping), we call:

```cpp
luaL_openselectedlibs(L, kRanaLoadLibs, 0);
```

- `kRanaLoadLibs` only opens: `_G`, `package`, `coroutine`, `debug`
  (needed for Pluto's own startup `debug.getinfo`, then stripped), `math`,
  `string`, `table`, `utf8`, `json`, `base64`, `regex`.
- The **preload mask is `0`** → nothing is registered for `require`.

After opening, the sandbox additionally:
- Strips globals: `io`, `os`, `debug`, `load`, `loadfile`, `dofile`, `ffi`,
  `socket`, `http`, `tls`, `crypto`, `wasm`.
- Empties `package.path`/`package.cpath`, nils `package.loadlib`, empties
  `package.preload`/`package.loaders`, and installs a **single restricted
  searcher** that resolves only `require("lib.<name>")` →
  `scripts_dir/lib/<name>.lua` (reviewed helpers; module names are `[A-Za-z0-9_]`
  segments, so no separators/traversal). Everything else — `ffi`, `socket`,
  `http`, `os`, ... — resolves to nothing.
- Purges `package.loaded` for all the above so a library cannot be resurrected.

### 3. Bridge allowlists (the only sanctioned escape hatches)
All privileged actions go through the `rana.*` C bridge and are gated:
- `rana.spawn(...)` — only binaries present in the `init.lua` allowlist.
- `rana.dispatch(...)` / `rana.respond(...)` — only `[commands.allowed]` keys.
- `rana.http_post(...)` — only hosts present in the endpoint allowlist.
- `rana.audio.decode_to_wav(...)` — in-process codec; no shell, no network.
- `rana.http_post` uses our own `http_do` (getaddrinfo + plaintext HTTP/1.1 with
  send/recv deadlines) and only talks to allowlisted hosts; it is **not** Pluto's
  `http` library. **TLS is not implemented**: `https` URLs are rejected at the
  scheme check rather than silently connecting in the clear — terminate TLS in a
  local proxy if you need it.

### 4. Script registration
- The daemon scans `scripts/*.pluto` at startup and reads each script's `meta`
  (name, description, actions, params, timeout, examples, flags). Scripts are
  self-describing and must declare what they do; `init.lua` only registers the
  binary/endpoint allowlists.
- A per-script execution timeout bounds blast radius. Scripts cannot touch the
  filesystem directly (`io`/`os` are stripped); the only file access is the
  host-side `lib/` searcher, which reads the reviewed `scripts/lib/*.lua` only.

## In-process hops
`talk.pluto` reaches `stt.pluto` and `ask.pluto` through the generic
`rana.dispatch` hop; `ask.pluto` builds its intent from `lib/llm.lua` +
`lib/fuzzy.lua`. Hops run in the **same locked-down state** — the runtime does
not grant them extra privileges. The one confirmation gate is `power.pluto`:
a destructive power action requires the client's explicit `params.confirm` and
otherwise fails closed (`SAFETY_GATE_FAILED`).

## Operational rules
- **Never** switch `new_state()` back to `luaL_openlibs`. That silently re-opens
  every dangerous library.
- Keep the compile-time flags above. They are belt-and-suspenders on top of the
  runtime mask.
- Treat every file under `scripts/` as untrusted input. Review generated
  scripts before persisting them.
- Optional deeper hardening (deferred): define `PLUTO_FFI_CALL_HOOK` /
  `PLUTO_HTTP_REQUEST_HOOK` to reject any FFI call / HTTP request at the
  call-site. The runtime mask already makes these unreachable, so this is
  defense-in-depth only.
